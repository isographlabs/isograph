# One-variant parent enums

`BracketItemParent` and `BracketTokenParent` are enums with one variant each, forced by the derive's field emission. This doc deletes them. The derive gains a second emission mode, selected per field: `#[resolve_field(parent_variant = V)]` wraps the container's path in variant `V` of the child's parent enum, and bare `#[resolve_field]` passes the container's path as the child's parent directly, with no enum and no variant. The implicit rule that the variant is named after the container goes away; a variant is always named at the field site. Two files change: `crates/resolve_position_macros/src/resolve_position_macro.rs` and `crates/isograph_parser/src/matched_brackets.rs`, on top of the tree as raw-items.md leaves it.

## Why the derive forces them

The landed field emission has exactly one shape:

```rust
// generated by resolve_position_macros/src/resolve_position_macro.rs
if self.field.location.contains(position) {
    let new_parent = <Child as ::resolve_position::ResolvePosition>::Parent::Container(self.path(parent).into());
    return self.field.item.resolve(new_parent, position);
}
```

`Container` is the deriving type's own name. A proc macro sees only the tokens of the item it is attached to, so at the field site it knows the container's name and nothing about the child's parent type — not whether it is an enum, not what variants it has. Naming a variant after the container is what lets the generated code compile without that knowledge; the compiler then checks that the variant exists.

When a child appears in several containers, the variant carries information — it says which container the resolution path went through. When a child appears in exactly one container, the natural parent type is the container's path itself, but the emission still writes `Parent::Container(..)`, and a path type has no variants. So the parent must be an enum with one variant whose only job is to satisfy the emission:

```rust
// from crates/isograph_parser/src/matched_brackets.rs
#[derive(Debug)]
pub enum BracketItemParent<'a> {
    MatchedBrackets(MatchedBracketsPath<'a>),
}

#[derive(Debug)]
pub enum BracketTokenParent<'a> {
    Bracketed(Box<BracketedPath<'a>>),
}
```

and every consumer pays a destructuring layer for a match with one arm:

```rust
// from crates/isograph_parser/src/matched_brackets.rs
let BracketItemParent::MatchedBrackets(level) = open.parent;
```

## The attribute

`#[resolve_field]` gains one optional argument:

```rust
// from crates/isograph_parser/src/matched_brackets.rs
#[derive(Debug, PartialEq, Eq, ResolvePosition)]
#[resolve_position(parent_type = MatchedBracketsPath<'a>, resolved_node = ResolvedBracketNode<'a>)]
pub struct Bracketed {
    #[resolve_field]
    pub opening: WithSpan<OpenBracket>,
    /// The wrapping `WithSpan`'s span runs from the opening's end to the closing's start.
    #[resolve_field(parent_variant = Bracketed)]
    pub children: WithSpan<MatchedBrackets>,
    #[resolve_field]
    pub closing: WithSpan<CloseBracket>,
}
```

Bare `#[resolve_field]` means the child's `Parent` type is the container's own path, and the emission passes `self.path(parent)` unwrapped. `#[resolve_field(parent_variant = Bracketed)]` means the child's `Parent` type is an enum, and the emission wraps the container's path in the named variant. The variant name comes from the field site, not from the container's name, so the source states the name the compiler checks.

Both misuses fail to compile inside the generated impl, at the derive site. Bare `#[resolve_field]` on a field whose child's parent is an enum is a mismatched-types error (expected the enum, found `PositionResolutionPath<..>`). `parent_variant` on a field whose child's parent is a path is "no variant or associated item named `V`". When a child with a path parent later gains a second container, its parent type becomes an enum, and each bare field site for that child stops compiling until it names a variant. Any other argument form (`#[resolve_field(foo)]`, `#[resolve_field = ..]`) is a compile error naming the two accepted forms.

## Macro changes

All in `crates/resolve_position_macros/src/resolve_position_macro.rs`. The parsed form of the attribute is a two-variant enum carried on `ResolveFieldInfo`:

```rust
// from crates/resolve_position_macros/src/resolve_position_macro.rs
/// How a field emission builds the value it passes as the child's parent.
enum ParentConstruction {
    /// Bare `#[resolve_field]`: the child's `Parent` type is the container's own
    /// path, and `self.path(parent)` is passed unwrapped.
    ContainerPath,
    /// `#[resolve_field(parent_variant = V)]`: the child's `Parent` type is an
    /// enum, and the container's path is wrapped in its variant `V`.
    EnumVariant(syn::Ident),
}

struct ResolveFieldInfo {
    field_accessor: proc_macro2::TokenStream,
    field_type: ResolveFieldInfoTypeWrapper,
    parent_construction: ParentConstruction,
}
```

### Emission

The container's name leaves the field emission entirely; `struct_name` still names the impl and the leaf `ResolvedNode` variant in `handle_data_struct`, but `generate_resolve_code` no longer takes it. The parent expression is built in one place and spliced into all four base-case arms.

Before:

```rust
            ResolveFieldInfoType::WithSpan(inner_type) => quote! {

            ResolveFieldInfoType::WithLocation(inner_type) => quote! {
                if let Some(span) = #field_expr.location.span() {
                    if span.contains(position) {
```

```rust
/// container's own path in both arms; the variant wrapping is the only difference.
fn new_parent_expr(
    parent_construction: &ParentConstruction,
    inner_type: &syn::Type,
) -> proc_macro2::TokenStream {
    match parent_construction {
        ParentConstruction::ContainerPath => quote!(self.path(parent)),
        ParentConstruction::EnumVariant(variant) => quote!(
            <#inner_type as ::resolve_position::ResolvePosition>::Parent::#variant(self.path(parent).into())
        ),

fn generate_resolve_code_recursive(
    wrapper: &ResolveFieldInfoTypeWrapper,
    parent_construction: &ParentConstruction,
    field_expr: proc_macro2::TokenStream,
```

In the `ContainerPath` arm the child's parent type is never named: `self.path(parent)` infers its parent type parameter from `resolve`'s signature, and the reflexive `From` in `path`'s bound is the only conversion. The `EnumVariant` arm is the landed emission with `#variant` in place of `#struct_name`.

### Parsing

The attribute's presence is detected as today; a present attribute's meta is then matched. Bare (`syn::Meta::Path`) is `ContainerPath`; a parenthesized list is parsed as one `syn::MetaNameValue` whose path must be `parent_variant` and whose value must be a single ident (syn 2 parses `Bracketed` as `Expr::Path`).

```rust
// from crates/resolve_position_macros/src/resolve_position_macro.rs
fn parse_parent_construction(
    attr: &syn::Attribute,
) -> Result<ParentConstruction, proc_macro2::TokenStream> {
    match &attr.meta {
        syn::Meta::Path(_) => ParentConstruction::ContainerPath.wrap_ok(),
        syn::Meta::List(_) => {
            let name_value = attr
                .parse_args::<syn::MetaNameValue>()
                .map_err(|e| e.to_compile_error())?;
            if let syn::Expr::Path(value) = &name_value.value
                && name_value.path.is_ident("parent_variant")
                && let Some(variant) = value.path.get_ident()
            {
                return ParentConstruction::EnumVariant(variant.clone()).wrap_ok();
            }
            Error::new_spanned(
                &attr.meta,
                "expected `#[resolve_field(parent_variant = SomeVariant)]`",
            )
            .to_compile_error()
            .wrap_err()
        }
        syn::Meta::NameValue(name_value) => Error::new_spanned(
            name_value,
            "expected `#[resolve_field]` or `#[resolve_field(parent_variant = SomeVariant)]`",
        )
        .to_compile_error()
        .wrap_err(),
    }
}
```

## The tree types

In `crates/isograph_parser/src/matched_brackets.rs`, both one-variant enums are deleted, and the types that declared them as `parent_type` declare the path type itself. `MatchedBracketsParent` stays an enum: a level really does have two kinds of parent, and its `Bracketed` variant keeps its `Box`, which breaks the type-level recursion. The direct parents are unboxed — `BracketedPath` contains `MatchedBracketsPath` contains `MatchedBracketsParent`, whose `Box` ends the cycle.

## Generated impls

The two containers with fields, expanded. `MatchedBrackets` descends with the direct emission through the `Vec` wrapper; `Bracketed` uses the direct emission for its own tokens and the variant emission for its interior, whose parent really is an enum.

```rust
// generated by resolve_position_macros/src/resolve_position_macro.rs
impl ::resolve_position::ResolvePosition for MatchedBrackets {
    type Parent<'a> = MatchedBracketsParent<'a>;
    type ResolvedNode<'a> = ResolvedBracketNode<'a>;

    fn resolve<'a>(
        &'a self,
        parent: Self::Parent<'a>,
        position: ::span::Span,
    ) -> Self::ResolvedNode<'a> {
        for item in self.0.iter() {
            if item.location.contains(position) {
                let new_parent = self.path(parent);
                return item.item.resolve(new_parent, position);
            }
        }

        return Self::ResolvedNode::MatchedBrackets(self.path(parent).into());
    }
}

impl ::resolve_position::ResolvePosition for Bracketed {
    type Parent<'a> = MatchedBracketsPath<'a>;
    type ResolvedNode<'a> = ResolvedBracketNode<'a>;

    fn resolve<'a>(
        &'a self,
        parent: Self::Parent<'a>,
        position: ::span::Span,
    ) -> Self::ResolvedNode<'a> {
        if self.opening.location.contains(position) {
            let new_parent = self.path(parent);
            return self.opening.item.resolve(new_parent, position);
        }
        if self.children.location.contains(position) {
            let new_parent = <MatchedBrackets as ::resolve_position::ResolvePosition>::Parent::Bracketed(self.path(parent).into());
            return self.children.item.resolve(new_parent, position);
        }
        if self.closing.location.contains(position) {
            let new_parent = self.path(parent);
            return self.closing.item.resolve(new_parent, position);
        }
        return Self::ResolvedNode::Bracketed(self.path(parent).into());
    }
}
```

In `MatchedBrackets::resolve`, `self.path(parent)` is a `PositionResolutionPath<&MatchedBrackets, MatchedBracketsParent>`, which is `MatchedBracketsPath`, which is `BracketItem`'s `Parent` — the reflexive `From` inside `path` is the only conversion. In `Bracketed::resolve`, the direct lines produce `BracketedPath` for the two token fields, and the `children` line wraps `self.path(parent).into()` — the standard boxing `From` — in `MatchedBracketsParent::Bracketed`, exactly as the landed emission does. The delegating enums (`BracketItem`, `RawToken`) and the five leaves generate the same code as before, with only their `Parent` associated types changed per the attributes above.

```rust
                assert_eq!(open.parent.inner.closing.item.0, Brace);
            }
            node => panic!("expected the open bracket leaf, got {node:?}"),
        }
        match tree.resolve(MatchedBracketsParent::Root, span_of(text, "}")) {
            ResolvedBracketNode::CloseBracket(close) => {
                assert_eq!(close.parent.inner.opening.item.0, Brace);
            }
            node => panic!("expected the close bracket leaf, got {node:?}"),
        }
    }

    #[test]
    fn an_ordinary_token_resolves_to_its_own_leaf() {
        let text = "foo { bar }";
        let tree = tree(text);
        match tree.resolve(MatchedBracketsParent::Root, span_of(text, "bar")) {
            ResolvedBracketNode::NonBracketToken(token) => {
                assert_eq!(token.inner.0, NonBracketTokenKind::Identifier);
                assert!(matches!(
                    token.parent.parent,
                    MatchedBracketsParent::Bracketed(_)
                ));
            }
            node => panic!("expected the token leaf, got {node:?}"),
        }
    }
```

The other resolution tests and all structural tests are unchanged. The existing suite covers both emission modes: the unmatched-token and ordinary-token tests exercise the direct emission into a level, the matched-pair test exercises the direct emission into a group, and the straddle and whitespace tests exercise the variant emission through `children`.
