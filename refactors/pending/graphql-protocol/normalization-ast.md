# GraphQL protocol: the normalization AST

Status: approved for implementation.

The normalization AST is the first real runtime artifact. It replaces the `export default {};` stub that `refactors/pending/artifact-set-and-types.md` change 3 writes at `<Entity>/<selectable>/normalization_ast.ts` for every `entrypoint` literal. The core builds it from the same `CompletedSelectionMap` that the protocol prints as the query text (`query-generation.md` in this directory), so the text and the AST match by construction: every selection the query selects is one AST node, under the alias the query gives it, and every conditional is one conditional AST node, with two stated exceptions (The asymmetries).

v1 has no runtime cache work. The artifacts are generated and asserted on by tests; `refactors/pending/runtime/pico-runtime.md` is the later consumer.

Upstream references are the checkout at `/Users/rbalicki/code/isograph` (commit `79e2a3c0`).

## End-user experience

`entrypoint.ts` is unchanged from artifact-set-and-types.md decision 4 (b): it imports `./normalization_ast` and exports it as `normalizationAst`. What changes is the imported module's default export, from `{}` to the object above.

The object is declared with the type `NormalizationAst`, so TypeScript checks every node against the types below and keeps each `kind` a literal type (`"Selection"`, not `string`). The module imports only that type; `import type` is erased, so the module has no runtime import.

What the AST shows:

- The nodes appear in the order of the query's lines, including the identity (`id`) the query adds.
- `responseKey` is the exact alias the query text prints before `:`. The normalizer reads `response[responseKey]` and never recomputes an alias from `selectableName` and `arguments`.
- `selectableName` and `arguments` remain because the store key resolves variables to their values (upstream `getParentRecordKey`, `isograph/libs/isograph-react/src/core/cache.ts:454-521`), which the response key does not.
- `root` is the record the top-level selections are written onto: the operation's root entity (`Query`) at the fixed root id (The record).
- `target` is `null` for a selection of a leaf entity. Otherwise it holds the target's selections and two independent facts about its records: `entity`, `Known` with the entity's name when the target is concrete and `Discriminator` when it is abstract, and `identity`, how the record id is found (The record).
- `discriminatorResponseKey` names, once for the artifact, the response key under which every composite response object holds its concrete entity's name. The `__typename` lines of the query have no node (The discriminator).
- `id` is both an ordinary `Selection` node, stored like any other leaf, and the `pets` target's `identity`, which the normalizer reads to key `Pet`'s records.

A refinement `asBlogItem { title }` under `newsfeed` is `{ kind: "Conditional", condition: { kind: "SelectionEquals", entityName: "BlogItem" }, identity: { kind: "Select", responseKey: "id" }, selections: [..] }` among `newsfeed`'s `target.selections`, after its selection nodes. `newsfeed`'s own target is a union: its `entity` is `{ kind: "Discriminator" }` and its `identity` is `{ kind: "Omit" }`. The conditional's records are of `BlogItem`, the entity its condition names, so it has no `entity`.

A selection of a root entity below the top level, `query { tags }` in `field Query.NestedQuery { greeting query { tags } }` on `query: Query!`, has the target `{ entity: { kind: "Known", name: "Query" }, identity: { kind: "Fixed", id: "__ROOT" }, selections: [tags] }`: the normalizer writes `tags` onto the `Query` record at `__ROOT`, the record `root` names. With `schema { query: RootQuery }`, the same holds for `RootQuery`, and `root` is `{ entity: "RootQuery", id: "__ROOT" }`.

A query whose completed map fails fails its AST too; there is no AST without query text and no query text without an AST.

## The discriminator

Every selection set under a composite selection selects the protocol's discriminator (query-generation.md, What the protocol tells the core; GraphQL's is `__typename`). The AST has no node for it. The normalizer reads it from a composite response object whose target's `entity` is `Discriminator`, and in no other case: a `Known` entity is taken from the AST, and the response's discriminator is not compared with it.

The runtime is protocol-neutral and hardcodes no GraphQL name. The AST carries the discriminator's response key once, as `discriminatorResponseKey`, which the core writes from `NetworkProtocol::discriminator()` (`SelectionKey { name: discriminator(), arguments: MergedArguments::default() }.normalization_alias()`). The alternative, a runtime environment option holding one string per environment, keeps the key out of every artifact, at the cost of a value the user configures to match the protocol the compiler used, with no check that the two agree.

Store values need no tag that marks a link: every store walk (normalize, read, check, garbage collection) goes through an AST whose `target` says which selections are links.

## The record

The AST states, where a record is keyed (every composite target, every conditional, and the operation's top level), which record a response object is written onto. The core holds both facts in the completed map (query-generation.md, Completion: `RecordEntity` and `CompletedIdentity`), and the AST copies them with the identity's selectable name replaced by its response key, which is what the runtime reads.

The entity (`NormalizationEntity` in TypeScript, the core's `RecordEntity` in Rust):

- `Known(name)`: the target entity is concrete (`Concreteness::Concrete`, GraphQL object types and so the root operation types): every response object is of `name`. Upstream's `concreteType` (`isograph/crates/artifact_content/src/normalization_ast_text.rs:68`).
- `Discriminator`: the target entity is abstract (GraphQL interfaces and unions): the response object's discriminator names its entity. Upstream's `concreteType: null`.

A conditional has no entity field: its records are of the entity its condition names.

The identity (`NormalizationIdentity`):

- `Select(response_key)`: the response key of the identity selection, which is also one of that selection set's `Selection` nodes. The normalizer keys the record by that value.
- `Omit`: the entity has no identity selection. The normalizer derives the record id from the parent record and the path (upstream `getDataIdOfNetworkResponse`, `isograph/libs/isograph-react/src/core/cache.ts:599-642`).
- `Fixed(id)`: the entity is a root entity (query-generation.md, Root entities): every response object of it is the one record at `id`, which is `"__ROOT"` (`FixedRecordId::root()`, upstream's `ROOT_ID`). The query selects no identity under it.

The conditional carries an identity because the response object's entity can have an identity its parent's target lacks: a union target (`Omit`) whose `asBlogItem` refinement selects on `BlogItem`, whose identity is `id`. The operation's top level carries `root`, the record `{ entity, id }` with `entity` the operation's root entity (`RootEntities.operation`) and `id` `FixedRecordId::root()`: the same rule as a nested selection of a root entity, so both write one record. The caller passes no root record.

Delta from upstream: upstream special-cases the GraphQL name `Query` at runtime (`if (__typename === 'Query') return ROOT_ID;`, `isograph/libs/isograph-react/src/core/cache.ts:614-618`, under its own `// TODO do not hard code this value here`) and starts every normalization at a root the caller passes. i2 decides both at compile time from the schema's root operation types, so the runtime names no GraphQL type and `schema { query: RootQuery }` works. A nested `Query` object inside a mutation payload is written onto `Query`'s root record, as upstream does.

The fixed id is in the artifact, not a runtime constant, so the runtime reads every record identity from the AST. Its cost is the six characters `"__ROOT"` per root target in every artifact.

`RecordEntity` and `FixedRecordId` are the core's (query-generation.md, The merged selection map); the AST uses `RecordEntity` as it is, because its payload is already what the runtime reads. `NormalizationIdentity` mirrors `CompletedIdentity` with the selectable name replaced by its response key. Each is an enum whose variants name their cases; neither fact is a `bool` or an `Option`.

## The asymmetries

The query text has one kind of line the AST has no node for, and the tests (Tests) account for it by removing those lines from the text side before comparing: the discriminator lines (`__typename: __typename`), selected in the query and implicit in the AST (The discriminator).

## The artifact's TypeScript type

```ts
// from libs/isograph-runtime/src/artifacts.ts
/** The default export of a `normalization_ast.ts` artifact. */
export type NormalizationAst = {
  /** The response key under which every composite response object holds its concrete
   * entity's name. */
  readonly discriminatorResponseKey: string;
  /** The record the top-level selections are written onto. */
  readonly root: NormalizationRootRecord;
  readonly selections: NormalizationSelectionSet;
};

/** The operation's root entity's one record. */
export type NormalizationRootRecord = {
  readonly entity: string;
  readonly id: string;
};

export type NormalizationSelectionSet = ReadonlyArray<NormalizationNode>;

export type NormalizationNode = NormalizationSelection | NormalizationConditional;

/** A selection of a selectable. */
export type NormalizationSelection = {
  readonly kind: "Selection";
  /** The alias the query text gives this selection: the key of its value in the response. */
  readonly responseKey: string;
  readonly selectableName: string;
  readonly arguments: Arguments | null;
  /** `null` when the target entity is a leaf. */
  readonly target: NormalizationCompositeTarget | null;
};

/** The selections on a composite target entity, and which records its response objects are. */
export type NormalizationCompositeTarget = {
  readonly entity: NormalizationEntity;
  readonly identity: NormalizationIdentity;
  readonly selections: NormalizationSelectionSet;
};

/** Which entity a response object's record is of. */
export type NormalizationEntity =
  /** Every response object is of `name`. */
  | { readonly kind: "Known"; readonly name: string }
  /** The response object's value under `discriminatorResponseKey` names its entity. */
  | { readonly kind: "Discriminator" };

/** How a response object's record id is found. */
export type NormalizationIdentity =
  /** The value under `responseKey`, one of the selection set's `Selection` nodes. */
  | { readonly kind: "Select"; readonly responseKey: string }
  /** Derived from the parent record and the path. */
  | { readonly kind: "Omit" }
  /** Every response object of the entity is the record `id`. */
  | { readonly kind: "Fixed"; readonly id: string };

/** Selections normalized onto the parent's record when `condition` holds. */
export type NormalizationConditional = {
  readonly kind: "Conditional";
  readonly condition: Condition;
  /** The identity of the condition's entity. */
  readonly identity: NormalizationIdentity;
  readonly selections: NormalizationSelectionSet;
};

/** When a conditional's selections apply: the record's entity is `entityName`. */
export type Condition = {
  readonly kind: "SelectionEquals";
  readonly entityName: string;
};

export type Arguments = ReadonlyArray<Argument>;
export type Argument = readonly [string, ArgumentValue];

export type ArgumentValue =
  | { readonly kind: "Variable"; readonly name: string }
  | { readonly kind: "Literal"; readonly value: number | boolean | null }
  | { readonly kind: "String"; readonly value: string }
  | { readonly kind: "Object"; readonly value: Arguments };
```

The names follow `docs-website/docs/design-docs/mental-model.md`: a node is a selection of a selectable (`kind: "Selection"`, `selectableName`), and a condition compares a selection's value (`SelectionEquals`). `target: NormalizationCompositeTarget | null` is the TypeScript form of the core's `NormalizationTarget::{Leaf, Composite(NormalizationCompositeTarget)}` (below): `Leaf` is `null`, `Composite` is the object. `NormalizationEntity` is `RecordEntity::{Known, Discriminator}` and `NormalizationIdentity` is `NormalizationIdentity::{Select, Omit, Fixed}`, each variant a `kind`. The entity and identity sit in the target object, not on the selection, so a leaf selection cannot carry them.

`Condition` has one kind in v1. It is the TypeScript form of the core `Condition` (query-generation.md), the same type the reader AST's refinements print (`refactors/pending/runtime/reader-ast.md`). Later, `@include` and `@skip` add `VariableEquals` (Later).

## How the artifact is constrained

Upstream's shape: a type import, a `const` declared with the type, and a default export of the binding:

```ts
import type { NormalizationAst } from "@isograph/runtime";
const normalizationAst: NormalizationAst = { discriminatorResponseKey: "__typename", selections: [..] };
export default normalizationAst;
```

Upstream's generated line is `import type {NormalizationAst} from '@isograph/react';` (`isograph/demos/pet-demo/src/components/__isograph/Mutation/SetTagline/normalization_ast.ts:1`, and the same line in each of the demo's 20 `normalization_ast.ts` files), followed by `const normalizationAst: NormalizationAst = {..};` and `export default normalizationAst;`. Deltas: the package is `@isograph/runtime`, because the types and the normalizer do not depend on React and i2 does not name a React-free package after React; the quotes and spacing are `swc_ecma_codegen`'s; the object's keys are i2's (deltas below).

The alternative is `export default {..} satisfies NormalizationAst;`. `satisfies` checks the value the same way and keeps the value's own literal type as the module's export type, so an importer of the module sees the exact nodes. The annotation is used because it matches upstream's generated artifacts, and because the artifact's consumers (`entrypoint.ts`, the runtime) only need `NormalizationAst`, not the literal type of one query's AST.

Deltas from upstream (`isograph/libs/isograph-react/src/core/entrypoint.ts:122-159`, `util.ts:10-33`):

- Upstream's `NormalizationAst` is `{ kind: "NormalizationAst", selections }` (`isograph/crates/artifact_content/src/entrypoint_artifact.rs:272-278`), whose `kind` distinguishes it from `NormalizationAstLoader`. i2 has no loader, so there is no `kind`; `discriminatorResponseKey` is new.
- Upstream's `Scalar` and `Linked` nodes are one `Selection` node. Upstream's normalizer tells them apart by `kind`; i2's by `target === null`. `fieldName` is `selectableName`; a `Linked` node's `selections` is `target.selections`.
- `identity` is new, on every composite target and conditional. Upstream's normalizer reads `id` by name (`getDataIdOfNetworkResponse`, `cache.ts:623-626`) and returns `ROOT_ID` for `__typename === 'Query'` (`cache.ts:614-618`); i2's `Fixed` states the root id per root target at compile time.
- `root` is new. Upstream's normalizer is passed the root record by its caller.
- `responseKey` is new. Upstream recomputes it per node in `getNetworkResponseKey` (`cache.ts:544-558`).
- `isFallible` is dropped. Upstream's normalizer never reads it on a normalization node (`cache.ts` reads only `concreteType`, `fieldName`, `arguments`, `selections`, `type`); pico-runtime.md drops it too.
- `concreteType: string | null` is `entity: { kind: "Known", name } | { kind: "Discriminator" }`. Upstream's normalizer names a linked record's type with `astNode.concreteType ?? networkResponseData.__typename` (`cache.ts:295-296`, `:322-323`); i2's normalizer reads the discriminator only under `Discriminator`. Upstream's `concreteType` is set from `ConcreteTargetEntityName` (`isograph/crates/isograph_schema/src/create_merged_selection_set.rs:820`); i2's `Known` from `Concreteness::Concrete` (query-generation.md).
- `InlineFragment { type, selections }` is `Conditional { condition, selections }`. Upstream's `normalizeInlineFragment` (`cache.ts:345-370`) tests `response.__typename === type` and normalizes the selections onto the parent record. `SelectionEquals { entityName: type }` is that test, named as data; the walk compares it with the record's entity (Semantics).
- `ArgumentValue` has no `Enum` kind, because `MergedValue` has none (query-generation.md), and `Literal`'s value is `number | boolean | null` where upstream's is `any`.
- No `storage` field. pico-runtime.md derives it from an `inline_types` config option that does not exist in i2.

## The condition

The core's completed map holds `Condition::SelectionEquals(EntityName)` for a refinement `asT` (query-generation.md). The AST holds the same `Condition`, unchanged: the entity is the only fact the runtime reads, and the discriminator's response key is already `NormalizationAst.discriminator_response_key`.

Before:

```rust

}
```

### Semantics

- A conditional node writes onto the parent's record. It creates no record and adds no segment to a response key path: its selections read keys of the same response object as the node's siblings, and write fields of the same record.
- `SelectionEquals(entityName)` holds when the record's entity is `entityName`. The record's entity is the one the walk is on: in `normalize`, the entity `recordLink` took for the record (the target's `Known` entity, or the response's discriminator value under `Discriminator`, store.md); in `check`, garbage collection, and `read`, the `entity` of the link the walk is at. Each walk writes the comparison inline as `===`, as upstream inlines `__typename === type` at each site (`isograph/libs/isograph-react/src/core/cache.ts:356`, `check.ts:193`, `garbageCollection.ts:159`). There is no `conditionHolds` function.
- A record's entity is always known when its conditionals are evaluated, so a condition never reads an absent or non-string value.

### Merging

Two conditionals in one selection set with equal conditions are one node whose selections are merged, because the map keys conditionals by `Condition` (query-generation.md, Merging). A conditional inside another is a nested node; nested conditions are never flattened into a conjunction. Under the current grammar no condition nests: `asT` targets an object type, and object types have no refinements.

### Abstract refinement targets

`SelectionEquals` on the discriminator cannot express "implements interface `I`": the response's `__typename` is always a concrete object type. That matches i2's refinements. Every `asT` target is an object type:

- `refinement_to` (`crates/graphql_network_protocol/src/protocol_data.rs:210-240`) returns a selectable only for `GraphQLEntityData::Object` (`:216-229`) and `None` for `Interface`, `Union`, `Leaf`, and `InputObject` (`:230-238`). Both callers go through it: `refinement_named` (`:197`) and `graphql_selectables` (`:327-332`).
- On an interface, `refinement_named` additionally requires the target to be an object whose `interfaces` contain the interface (`:182-188`). On a union, it requires membership (`:181`) and then `refinement_to` filters to objects.

Upstream's are concrete too: refinements are created per `concrete_child_entity_name` (`isograph/crates/graphql_network_protocol/src/nested_server_schema/parse_nested_server_schema.rs:362-406`), the subtype map gets interface entries only from object types' `implements` (`:527-532`), and union entries from member types (`:659-665`).

### Representation in the artifact

The artifact holds the condition as data (`{ kind: "SelectionEquals", entityName: "Pet" }`).

Reasons: v1 tests assert facts about artifacts, and data compares (`===` on the fields, structural equality on the object) while functions do not; the artifact stays plain object literals (AGENTS.md, TypeScript: "Generated artifacts are plain object literals and types").

The alternative is a generated function per condition, `condition: (response, variables) => response.__typename === "Pet"`. Its costs: `ArtifactValue` gains a function-expression variant and the SWC printer an arrow-function and expression layer (`===`, member access) that no other artifact needs; a test can only call it on inputs, not compare it; two equal conditions are two distinct function objects, so the runtime cannot key or deduplicate by condition; and the artifact contains code, which the TypeScript section excludes. It would also read the response, which `check`, garbage collection, and `read` do not have.

## The core AST type

The AST is a core type, built in the core from the completed map, and printed by the host language. `typescript_artifacts` reads it without depending on `graphql_network_protocol` (AGENTS.md: core crates do not depend on it).

```rust
// from crates/isograph_compiler/src/normalization_ast.rs
/// The normalization AST of one query's response.
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct NormalizationAst {
    /// The response key of the protocol's discriminator, in every composite response object.
    pub discriminator_response_key: NormalizationAlias,
    /// The record the top-level selections are written onto.
    pub root: NormalizationRootRecord,
    pub selections: NormalizationSelectionSet,
}

/// The operation's root entity's one record.
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct NormalizationRootRecord {
    pub entity: EntityName,
    pub id: FixedRecordId,
}

/// The nodes a normalizer walks, in query order. Empty for a composite selection whose only
/// selection is the discriminator.
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct NormalizationSelectionSet(pub Vec<NormalizationNode>);

#[derive(Clone, Debug, PartialEq, Eq)]
pub enum NormalizationNode {
    Selection(NormalizationSelection),
    Conditional(NormalizationConditional),
}

/// A selection of a selectable.
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct NormalizationSelection {
    pub response_key: NormalizationAlias,
    pub selectable_name: SelectableName,
    pub arguments: NormalizationArguments,
    pub target: NormalizationTarget,
}

/// Whether a selection's target entity has selections.
#[derive(Clone, Debug, PartialEq, Eq)]
pub enum NormalizationTarget {
    Leaf,
    Composite(NormalizationCompositeTarget),
}

/// The selections on a composite target entity, and which records its response objects are.
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct NormalizationCompositeTarget {
    pub entity: RecordEntity,
    pub identity: NormalizationIdentity,
    pub selections: NormalizationSelectionSet,
}

/// The records of a conditional's response objects are of its condition's entity.
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct NormalizationConditional {
    pub condition: Condition,
    pub identity: NormalizationIdentity,
    pub selections: NormalizationSelectionSet,
}

/// How a response object's record id is found.
#[derive(Clone, Debug, PartialEq, Eq)]
pub enum NormalizationIdentity {
    /// The response key of the identity selection, one of the selection set's nodes.
    Select(NormalizationAlias),
    /// The entity has no identity selection; the normalizer derives the record id.
    Omit,
    /// The entity is a root entity: every response object of it is the record with this id.
    Fixed(FixedRecordId),
}

/// Arguments in `MergedArguments` order: sorted by name, no name twice.
#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct NormalizationArguments(pub Vec<NormalizationArgument>);

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct NormalizationArgument {
    pub name: ArgumentName,
    pub value: NormalizationValue,
}

/// `MergedValue` with integers narrowed to GraphQL's 32-bit `Int`.
#[derive(Clone, Debug, PartialEq, Eq)]
pub enum NormalizationValue {
    Variable(VariableName),
    String(StringLiteralValue),
    Integer(i32),
    Boolean(Boolean),
    Null,
    Object(Vec<NormalizationObjectEntry>),
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct NormalizationObjectEntry {
    pub name: ValueKeyName,
    pub value: NormalizationValue,
}
```

`NormalizationSelectionSet` is a `Vec`, not a `NonEmpty`: the query's selection set under a composite selection is never empty, because it holds the discriminator, but the AST leaves the discriminator implicit, so `stats { X @loadable }` on an entity with no identity is a node whose target's `selections` is `[]` and whose `identity` is `Omit`. `RecordEntity` and `FixedRecordId` are query-generation.md's (`crates/isograph_compiler/src/merged_selection.rs`). `Boolean` is `isograph_parser::Boolean`. `NormalizationArguments` keeps `MergedArguments`' order because the TypeScript `Arguments` is a list, and the store key upstream builds from it (`getParentRecordKey`) depends on its order; sorted arguments give one store key per selection key. An empty `NormalizationArguments` prints as `arguments: null` (upstream `get_serialized_field_arguments`, `isograph/crates/artifact_content/src/generate_artifacts.rs:483-485`).

`Integer(i32)` is narrower than `MergedValue::Integer(i64)` because the TypeScript value is a `number` (`f64`), which represents every `i32` exactly (`f64::from(i32)`), and the workspace denies `cast_precision_loss`. GraphQL `Int` is 32-bit (spec 3.5.1), so a literal outside `i32` is a query the server rejects; the builder returns `IntegerOutOfRange`, which fails the query. The alternative, an `ArtifactValue` integer variant printed from its decimal text that keeps `i64`, is not taken: the server rejects such a query anyway, and a value beyond 2^53 loses precision once the TypeScript source is parsed as a `number`.

## The builder

```rust
// from crates/isograph_compiler/src/normalization_ast.rs
/// The normalization AST of the response to the operation whose top-level selections are
/// `selections`.
pub fn normalization_ast(
    selections: &CompletedSelectionMap,
    discriminator_response_key: NormalizationAlias,
    root_entity: EntityName,
) -> Result<NormalizationAst, IntegerOutOfRange>;

/// One node per selection of `selections`, in key order, without the discriminator.
fn normalization_selection_set(
    selections: &CompletedSelectionMap,
    discriminator_response_key: &NormalizationAlias,
) -> Result<NormalizationSelectionSet, IntegerOutOfRange>;

/// `selection` as a node; `None` for the discriminator.
fn normalization_node(
    selection: &CompletedSelection,
    discriminator_response_key: &NormalizationAlias,
) -> Option<Result<NormalizationNode, IntegerOutOfRange>>;

/// `identity` with a `Select` name replaced by that selection's response key.
fn normalization_identity(identity: &CompletedIdentity) -> NormalizationIdentity;

fn normalization_arguments(
    arguments: &MergedArguments,
) -> Result<NormalizationArguments, IntegerOutOfRange>;

fn normalization_value(value: &MergedValue) -> Result<NormalizationValue, IntegerOutOfRange>;

#[derive(Clone, Debug, PartialEq, Eq, thiserror::Error)]
#[error("`{0}` is outside GraphQL's 32-bit `Int` range.")]
pub struct IntegerOutOfRange(pub i64);
```

`normalization_ast` is `NormalizationAst { discriminator_response_key, root: NormalizationRootRecord { entity: root_entity, id: FixedRecordId::root() }, selections: normalization_selection_set(selections, ..)? }`. `query_for_entrypoint` passes `roots.operation` as `root_entity` (query-generation.md, The operation's selections and variables).

`normalization_selection_set` is `selections.iter().filter_map(normalization_node)` collected into a `Result<Vec<_>, _>`. `normalization_node`:

- `Discriminator` is `None` (The discriminator).
- `Identity(name)` is `Selection { response_key: SelectionKey { name, arguments: MergedArguments::default() }.normalization_alias(), selectable_name: name, arguments: NormalizationArguments::default(), target: Leaf }`.
- `Selectable(selection)` is `Selection { response_key: selection.key.normalization_alias(), selectable_name: selection.key.name, arguments: normalization_arguments(selection.key.arguments)?, target }`, with `target` `Leaf` for `CompletedSelectionTarget::Leaf` and, for `Composite(target)`, `Composite(NormalizationCompositeTarget { entity: target.entity.clone(), identity: normalization_identity(target.identity.reference()), selections: normalization_selection_set(target.selections, ..)? })`.
- `Conditional(conditional)` is `Conditional { condition: conditional.condition.clone(), identity: normalization_identity(conditional.identity.reference()), selections }`.

`normalization_identity` maps `Select(name)` to `NormalizationIdentity::Select(SelectionKey { name, arguments: MergedArguments::default() }.normalization_alias())`, the same response key as the `Identity` node, `Omit` to `Omit`, and `Fixed(id)` to `Fixed(id.clone())`. It decides nothing: `complete` decided both facts (query-generation.md, Completion).

`normalization_value` maps `MergedValue` variant for variant; `Integer(n)` is `i32::try_from(n)`, `Err` is `IntegerOutOfRange(n)`.

The builder has no invariant to check. A condition's key is a map key, so no two conditionals of one selection set are equal; the discriminator is in every composite selection set by `complete`.

Upstream's origin is `generate_normalization_ast_text` (`isograph/crates/artifact_content/src/normalization_ast_text.rs:9-91`), called on the same `MergedSelectionMap` as `generate_query_text` (`isograph/crates/artifact_content/src/entrypoint_artifact.rs:127-212`, `:154` and `:212`). Deltas:

- Both walk the core's merged map. Upstream's map holds `__typename` and `id` (inserted during the merge, `isograph/crates/isograph_schema/src/create_merged_selection_set.rs:1414-1463`); i2's completed map holds the discriminator and the identity, and the AST omits the discriminator.
- Upstream builds a string with `format!`; i2 builds a value the host prints.
- Upstream skips `ClientObjectSelectable` (`normalization_ast_text.rs:73`) and the query text skips it too; i2's map never holds a client pointer (query-generation.md, Client pointers).
- Upstream's AST and text disagree on aliases: its text aliases fields with arguments and its AST has none (the runtime recomputes them); i2's AST carries every alias as `responseKey`.

## Later

- Selecting `__typename` only where the normalizer reads it. v1 carries the concrete entity as `entity: Known(..)` (The record) and still selects the discriminator under every composite selection. Selecting it only under `Discriminator` targets and inside refinements, as upstream does (`isograph/crates/isograph_schema/src/create_merged_selection_set.rs:1419-1427`), is an efficiency change: fewer bytes per response. It changes `complete`'s step 4 and the printer tests that expect `__typename` first in every block.
- `Node`-fetched entrypoints and refetch queries (`node(id: $id) { ... on T { .. } }`): the `... on T` is a `Conditional` (`SelectionEquals(T)`) in the AST, as upstream keeps an `InlineFragment` there (`isograph/demos/pet-demo/src/components/__isograph/BlogItem/BlogItemMoreDetail/normalization_ast.ts:16-41`), because the id comes from the caller and another entity's id returns `{ __typename: "Other" }` without `T`'s fields. entrypoints.md, Later.
- `VariableEquals`. `@include(if: $x)` and `@skip(if: $x)` become conditionals: the merge key gains the condition, so `f @include(if: $a)` and `f` are two entries; the printer prints the directive; `Condition` gains `VariableEquals { name, value }`, which holds when `variables[name] === value`; every walk then switches on the condition's `kind`, and `check`, garbage collection, and `read` receive the variables. Nothing produces it in v1, so v1 has no such variant.
- Abstract refinement targets (interfaces, unions). `SelectionEquals` alone cannot express them, because the value the response holds under `__typename` is the concrete type name (`Pet`), never a fixed value that stands for the abstract type. Inside the fragment, the query selects one more aliased selection, `... on Named { __refinement__Named: __typename .. }`. The server returns that key only when the object is of the abstract type, so the condition is "the response object has the key `__refinement__Named`": a variant `SelectionPresent { response_key }`, with no list of concrete types and no subtype check at runtime. The key belongs to the same response object as the fragment's siblings (a fragment adds no path segment), and it is selected inside the fragment rather than before it. The generator owns the `__refinement__` prefix, so the alias cannot collide with a normalization alias: a name starting with `__` is reserved for introspection (GraphQL spec 3.4.1), and every normalization alias starts with its selectable name.

### Objects without an identity field (open area, not v1)

This is not a v1 change and has no held option. It is an optimization that does not matter for v1, and an open area of thinking.

What v1 does, upstream's behavior: a linked field whose target has no identity field (a `date` object with `day`, `hour`, `minute`) is a `Selection` node whose target has `identity: { kind: "Omit" }` and whose `selections` list every selection of it, like any other composite selection. The normalizer writes it as its own record, whose identity is derived from the parent record, the field name, and the arguments (`getDataIdOfNetworkResponse`, `isograph/libs/isograph-react/src/core/cache.ts:599-642`: `<parent typename>:<parent id>.<fieldName>`, then `.<index>` in a list, then one chunk per argument). The parent record holds a link to that record.

The open idea: such an object has no identity of its own, so the normalizer could merge it directly into the parent record, possibly deeply (a `date` inside a `schedule` inside a `Pet`, all stored on `Pet`'s record). The normalization AST then might not need to list the object's subfields: the normalizer would copy the response object's value under the parent's `responseKey` without walking it.

Open question: an object with an identity field nested inside an identity-less object (`Pet.schedule { date { .. } owner { id .. } }`, where `schedule` has no identity and `owner` has `id`). Copying `schedule` without walking it would store `owner` inside `Pet`'s record instead of as its own record, so updates to that `Owner` elsewhere would not reach it. The AST would have to list the subfields down to every object with an identity field. The user's intuition is that this shape looks like a schema bug, but it is a common GraphQL pattern. The identity-less object's identity might then have to come from its relationship with the parent, as Relay derives a client id from the parent record and the field path, rather than the object being merged into the parent record.
