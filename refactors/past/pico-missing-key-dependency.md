# pico depends on missing keys

Every keyed read of a source or singleton inside a memo records a dependency on that key, whether a source is set there or not. A read of a missing key records the dependency at the initial epoch and does not write storage. Inserting a new key advances the epoch, so the reader re-runs. Removing a source takes its node's value and advances the epoch, which is also a change. A one-key lookup is `db.try_get(T::id_for_key(&key))`. `tracked()` on a `#[tracked]` map is for iteration only.

## Changes

1. pico: a read of a missing key is a dependency. Landed upstream as isograph #994 (pinned first by #995), reworked by #1000, and brought into i2 in c17d9e396, a4404f418, and f81153e60. It differs from this doc's absent-node design: #1000 inserts nothing on a read, `source_value_and_epoch` returns `(None, Epoch::new())` for a key with no node, `set_source` advances the epoch on every insert, and source nodes live in a `HashMap<Key, SourceNode>` instead of a `DashMap` index plus a `BoxcarVec`. The equal re-set follow-up landed as upstream #998/#999 (i2 20d9aef85, 64146bebc): an equal re-set leaves the node unchanged.
2. pico / pico_macros: the `#[tracked]` counter has no `Default`. `Counter::next(previous: Option<&Self>)` replaces `Counter::increment` and the `C::default()` branch. Landed in i2 in c736cc785, not upstream. Below.
3. pico / pico_macros: keyed source reads without a value. Shipped as `try_get` / `id_for_key` instead of this doc's `get_if_present` / `T::source_id`, in upstream #1003, brought into i2 in 6650c6530. `Storage::get` and `get_singleton` call `try_get`.
4. i2: keyed lookups read the source key. `file_contents` reads `try_get(EditorBuffer::id_for_key(..))` then `try_get(DiskFile::id_for_key(&path))`, and `editor_buffer_source_id` / `disk_file_source_id` are deleted (27b023a11). AGENTS.md "pico tracked maps" and pico.md "Tracked maps" state the rule and drop tracked-on-miss (6a1c79a70). The `extract_iso_literals` and `IsographDb::disk_file` call sites this doc listed were already gone: `extract_iso_literals` reads `file_contents`, and `disk_file` was deleted in lsp-open-files.md change 7.

## Change 2: the `#[tracked]` counter has no `Default`

pico.md "No `Default` for missing data" states the rule: a type does not implement `Default` to stand in for "not written yet". The counter's first value comes from `next(None)`.

`crates/pico/src/view.rs`, before (lines 5-7 and 67-74):

```rust
// external isograph/crates/pico/src/view.rs
pub trait Counter: Singleton + Default + Copy + Eq + 'static {
    fn increment(self) -> Self;
}

    pub fn tracked(&'a mut self) -> &'a mut T {
        let next = self
            .db
            .get_singleton::<C>()
            .map_or(C::default(), |c| c.increment());
        self.db.set(next);
        (self.projector)(self.db)
    }
```

After:

```rust
// from crates/pico/src/view.rs
pub trait Counter: Singleton + Eq + 'static {
    /// The value written after `previous`, or the first value when `previous` is `None`.
    fn next(previous: Option<&Self>) -> Self;
}

    pub fn tracked(&'a mut self) -> &'a mut T {
        let next = C::next(self.db.get_singleton::<C>());
        self.db.set(next);
        (self.projector)(self.db)
    }
```

The `Copy` bound and the generated `Copy` derive go too: `increment(self)` from `&C` was their only use. `View::tracked` (`view.rs:29-32`) is unchanged; inside a memo its `get_singleton` records a dependency on the counter's key, at the initial epoch when the counter was never written.

`crates/pico_macros/src/db_macro.rs`, before (lines 73-80):

```rust
// external isograph/crates/pico_macros/src/db_macro.rs
        aux_struct_defs.push(quote! {
            #[derive(Clone, Copy, Default, PartialEq, Eq, Hash, ::pico_macros::Singleton)]
            pub struct #counter_ident(u64);
            impl ::pico::Counter for #counter_ident {
                #[inline]
                fn increment(self) -> Self { Self(self.0.wrapping_add(1)) }
            }
        });
```

After:

```rust
// from crates/pico_macros/src/db_macro.rs
        aux_struct_defs.push(quote! {
            #[derive(Clone, PartialEq, Eq, Hash, ::pico_macros::Singleton)]
            pub struct #counter_ident(u64);
            impl ::pico::Counter for #counter_ident {
                #[inline]
                fn next(previous: ::core::option::Option<&Self>) -> Self {
                    previous.map_or(Self(0), |previous| Self(previous.0.wrapping_add(1)))
                }
            }
        });
```

Generated for `disk_file_map`, before:

```rust
// external isograph/crates/pico_macros/src/db_macro.rs
// generated by crates/pico_macros/src/db_macro.rs
#[derive(Clone, Copy, Default, PartialEq, Eq, Hash, ::pico_macros::Singleton)]
pub struct DiskFileMapCounter(u64);
impl ::pico::Counter for DiskFileMapCounter {
    #[inline]
    fn increment(self) -> Self { Self(self.0.wrapping_add(1)) }
}
```

After:

```rust
// generated by crates/pico_macros/src/db_macro.rs
#[derive(Clone, PartialEq, Eq, Hash, ::pico_macros::Singleton)]
pub struct DiskFileMapCounter(u64);
impl ::pico::Counter for DiskFileMapCounter {
    #[inline]
    fn next(previous: ::core::option::Option<&Self>) -> Self {
        previous.map_or(Self(0), |previous| Self(previous.0.wrapping_add(1)))
    }
}
```

The value sequence is unchanged (0, then +1). No behavior changes: `map_or(C::default(), ..)` and `next(None)` write the same first value. `grep -rn "impl.*Counter for\|\.increment()" crates` outside `crates/pico` finds only the generator above. `tracking_field/correctness.rs`, `efficiency.rs`, and `never_written.rs` cover `MutView::tracked`. `first_tracked_write_writes_counter_zero` (`never_written.rs`) asserts that the first tracked write of a never-written map writes its counter as 0.

## Upstream divergence

AGENTS.md says pico and pico_macros are kept unchanged from upstream isograph, and that a deviation from upstream names its reason. `diff -r` of `crates/pico` and `crates/pico_macros` against `../isograph` differs today in single-line string literals, one `.to()` for `.into()` (`database.rs`), upstream's `memo_ref_postfix` (#1001, not applied), i2's `tests/absent_source/try_get.rs`, and `.values()` for `.iter()` in `tests/tracking_field/correctness.rs`. Change 2 diverges: `Counter::next` replaces `Counter::increment` and the counter loses `Default`. Its stated reason is the pico.md rule above; it fixes no bug. It needs the user's approval, or an upstream isograph PR that removes the divergence. The user approved it for i2. AGENTS.md first paragraph, first sentence, as landed with change 2:

```text
From upstream isograph we keep pico and pico_macros (unchanged except that the `#[tracked]` counter has no `Default`, and `Counter::next(previous: Option<&Self>)` replaces `Counter::increment`), the swc plugin and its dependency chain (isograph_config, common_lang_types, string_key_newtype, prelude), resolve_position, the relay crates, the docs website, and the build process.
```

## Resolved decisions

1. Test counters. Decided (a): the pico tests count memo-body executions with a per-test `static AtomicUsize`, as landed in upstream #995/#994/#1003 (`crates/pico/tests/absent_source`, `tracking_field/never_written.rs`).
2. Postfix in pico. Decided (a) for pico: upstream #1002 (i2 6a1b3ef83, 4f89267bf) makes pico depend on `prelude` and use `Postfix`, and the postfix lint covers `crates/pico`. pico_macros does not depend on `prelude`; change 2's generator needs nothing from it.
3. `source_node_changed_since` on a key with no node. Dropped: #994 kept `None => true`, and #1000 replaced the lookup with `source_value_and_epoch`, which returns the initial epoch for a key with no node. No panic is added.
