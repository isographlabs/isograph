# resolve_position: parents construct through `From`

The macro's two parent-construction sites stop naming variants. Enum delegation arms call `inner.resolve(parent.into(), position)` instead of `inner.resolve(parent, position)`, and field emissions call `<Child as ResolvePosition>::Parent::from(self.path(parent))` instead of `<Child as ResolvePosition>::Parent::#container(self.path(parent).into())`, so a parent type can be an enum with a hand-written `From`, or a plain path alias satisfied by the reflexive `From` — the convention's "parent path directly" case, which variant-naming made impossible.

Today a payload's `Parent` type must equal its containing enum's `Parent` type, because the parent is passed through untouched. With the conversion, a payload may have its own parent enum, one total `From` away: the path then records which position the node sits in, and one node type can appear in several positions. No current design needs it: the close bracket's two positions are served by a stray newtype whose hand-written resolve builds the parent, with no macro change. Parked until a delegation arm genuinely needs a conversion.

This ships alone with no behavior change: `impl<T> From<T> for T` makes the conversion the identity for every existing derive.

## The change

In `resolve_position_macro.rs`: `handle_data_enum`'s arm emission, and every field case in `generate_resolve_code_recursive`.

The delegation arms, before:

```rust
quote! {
    #enum_name::#variant_name(inner) => inner.resolve(parent, position)
}
```

After:

```rust
quote! {
    #enum_name::#variant_name(inner) => inner.resolve(parent.into(), position)
}
```

The field cases, before:

```rust
// from crates/resolve_position_macros/src/resolve_position_macro.rs
            ResolveFieldInfoType::WithSpan(inner_type) => quote! {
                if #field_expr.location.contains(position) {
                    let new_parent = <#inner_type as ::resolve_position::ResolvePosition>::Parent::#struct_name(self.path(parent).into());
                    return #field_expr.item.resolve(new_parent, position);
                }
            },
```

After:

```rust
// from crates/resolve_position_macros/src/resolve_position_macro.rs
            ResolveFieldInfoType::WithSpan(inner_type) => quote! {
                if #field_expr.location.contains(position) {
                    let new_parent =
                        <#inner_type as ::resolve_position::ResolvePosition>::Parent::from(
                            self.path(parent),
                        );
                    return #field_expr.item.resolve(new_parent, position);
                }
            },
```

and identically in the `WithLocation`, `WithEmbeddedLocation`, and `GraphQLTypeAnnotation` cases; `path`'s `TParent` infers from `From`'s argument type. Existing parent enums keep compiling by gaining one `From` impl per container path where the named variants used to be constructed.

The generated code for `BracketItem<BracketsMatched>`'s delegation, written out, after:

```rust
// generated by resolve_position_macros/src/resolve_position_macro.rs
impl ::resolve_position::ResolvePosition for BracketItem<BracketsMatched> {
    type Parent<'a> = BracketItemParent<'a>;
    type ResolvedNode<'a> = ResolvedBracketNode<'a>;

    fn resolve<'a>(
        &'a self,
        parent: Self::Parent<'a>,
        position: ::span::Span,
    ) -> Self::ResolvedNode<'a> {
        match self {
            BracketItem::Inner(inner) => inner.resolve(parent.into(), position),
            BracketItem::Bracketed(inner) => inner.resolve(parent.into(), position),
            BracketItem::StrayClose(inner) => inner.resolve(parent.into(), position),
        }
    }
}
```

Every payload here has `Parent = BracketItemParent`, so each `.into()` is the reflexive `From` and the impl is unchanged in behavior.
